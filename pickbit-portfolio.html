Overview

프로젝트 개요

PickBit은 일반 판매 없이 경매만을 다루는 C2C 마켓플레이스입니다. 판매자가 상품을 등록하고 경매를 생성하면, 구매자들이 실시간으로 입찰에 참여하여 최고가 입찰자가 낙찰받는 구조입니다.

다수의 사용자가 동시에 입찰하는 상황에서의 데이터 정합성을 핵심 과제로 설정하고, Redis 분산 락을 통한 동시성 제어와 WebSocket(STOMP)을 통한 실시간 입찰 현황 전달을 중점적으로 설계했습니다.

Gradle 멀티모듈 모노레포 구조로 서비스 간 코드를 공유하면서도 각 서비스가 독립적으로 빌드·배포 가능하도록 설계했습니다.

Features

핵심 기능

분산 락 기반 입찰
Redisson RLock으로 동일 경매에 대한 동시 입찰을 직렬화하여 race condition을 방지합니다.
  • tryLock(5s wait, 10s lease) 타임아웃 설정
  • 락 획득 후 가격 검증 → 저장 → 알림 원자적 처리
  • 이전 최고가 입찰의 상태를 OUTBID로 자동 변경
실시간 입찰 알림
STOMP over WebSocket으로 경매 참여자에게 입찰 현황을 즉시 전달합니다.
  • 경매별 토픽 /topic/auctions/{id} 구독
  • 입찰 발생 시 현재가·입찰자·시각 실시간 브로드캐스트
  • SockJS 폴백으로 WebSocket 미지원 환경 대응
QueryDSL 동적 검색
다양한 조건을 조합하는 타입 안전 동적 쿼리로 상품 검색을 지원합니다.
  • 키워드 · 카테고리 · 가격 범위 · 판매자 조건 조합
  • 커서 기반 페이지네이션 (무한 스크롤)
  • QueryBaseRepository로 공통 패턴 추출
경매 생명주기 자동화
스케줄러가 매 분 경매 상태를 자동 전이하고 낙찰 처리를 수행합니다.
  • SCHEDULED → ACTIVE (시작 시각 도래 시)
  • ACTIVE → ENDED (종료 시각 도래 시)
  • 종료 시 최고가 입찰자를 낙찰자로 자동 결정
상품 관리 + 카테고리
상품 CRUD, 카테고리 관리, 이미지 업로드를 포함한 상품 도메인 전체를 구현합니다.
  • 상품 상태 추적 (ACTIVE → AUCTION_COMPLETED → DELETED)
  • 썸네일/상세 이미지 분류 관리
  • 카테고리 활성화/비활성화 토글
공통 라이브러리 모듈
서비스 간 공통 관심사를 Library 모듈로 추출하여 코드 중복을 제거합니다.
  • BaseEntity (JPA 감사), GlobalExceptionHandler (RFC 7807)
  • QueryBaseRepository (QueryDSL 공통 패턴)
  • LoggingFilter (HTTP 요청/응답 로깅 + MDC)
Technical Decisions

설계 결정

1
분산 락 선택 — DB 비관적 락 대신 Redis Redisson
DB 비관적 락(SELECT ... FOR UPDATE)은 DB 커넥션을 점유하며 타임아웃 제어가 어렵습니다. Redisson RLock은 tryLock(waitTime, leaseTime)으로 대기·해제 시간을 명시적으로 제어할 수 있고, DB 부하 없이 애플리케이션 레벨에서 동시성을 관리할 수 있어 선택했습니다.
2
스냅샷 패턴 — 경매 엔티티에 상품 정보 복제
경매 생성 시 productName, productThumbnailUrl, sellerNickname을 경매 엔티티에 복사합니다. 상품이 수정·삭제되더라도 이미 생성된 경매의 정보가 변하지 않아 데이터 무결성을 보장하고, 서비스 간 불필요한 조회 호출을 제거합니다.
3
서비스 간 통신 — Feign 대신 Spring RestClient
Spring 6.1+에서 제공하는 RestClient는 별도 의존성 없이 선언적 HTTP 클라이언트를 구성할 수 있습니다. 현재 서비스 간 통신 빈도가 낮고(경매 생성 시 1회), Spring Cloud 전체를 도입할 필요가 없어 가벼운 RestClient를 선택했습니다.
4
모노레포 + 독립 DB — 서비스 경계 유지
각 서비스는 별도 MySQL 스키마(pickbit_product_server, pickbit_auction_server)를 사용하여 데이터 소유권을 명확히 합니다. 코드는 모노레포에서 공유 Library 모듈을 통해 중복을 줄이되, 런타임에는 독립적으로 동작하여 향후 폴리레포 전환이 용이합니다.
5
공통 예외 처리 — RFC 7807 Problem Detail
Library 모듈의 GlobalExceptionHandler가 모든 서비스의 예외를 RFC 7807 형식으로 통일합니다. timestamp, path, fieldErrors 등 구조화된 에러 응답을 반환하여 클라이언트가 일관된 에러 처리 로직을 사용할 수 있습니다.
6
테스트 전략 — TestContainers로 실환경 DB 보장
H2 인메모리 DB는 MySQL과 문법·동작 차이가 있어 통합 테스트의 신뢰도가 낮습니다. TestContainers로 실제 MySQL 8.4 컨테이너를 띄워 운영 환경과 동일한 조건에서 테스트하고, @ServiceConnection으로 설정을 자동 연결합니다.
